メインフレームのオープン化 ～アセンブラ→COBOL変換編⑪～
CLC命令の比較処理とTHEN／ELSEの分岐ロジックを確認する

カテゴリ：メインフレーム・レガシーシステム 投稿日：2026年11月15日

はじめに

アセンブラからCOBOLへの変換では、CLC（Compare Logical Character）命令の比較結果と分岐命令の関係を正しく理解することが重要です。
今回は「CLC（Compare Logical Character）」と呼ばれる比較命令について確認した際の話です。
比較処理そのものはシンプルに見えますが、比較結果に応じて分岐するロジックを正しく理解していないと、期待とは逆の動作になってしまいます。
特に THEN（真）／ELSE（偽）の解釈 には注意が必要だと感じました。

CLC命令とCOBOL変換の構造

CLCは、2つのデータを比較するための命令です。
アセンブラのソースでは、以下のような形を見かけます。 

CLC 項目A,項目B
BE LABEL-A

変換後のCOBOLでは、次のような処理になることが多くあります。 

IF 項目A = 項目B
    ...
ELSE
    ...
END-IF

一見すると分かりやすいのですが、変換結果を確認する際には以下のポイントを特に意識して確認しました。

  • 比較条件は本当に一致しているか
  • THEN側が真の場合の処理か
  • ELSE側が偽の場合の処理か
  • 条件が反転していないか

もしTHENとELSEを取り違えてしまうと、プログラム自体は正常に動作しているように見えても、結果が期待値と異なってしまいます。

比較処理を確認する際の4ステップ

実際の変換結果を確認する際は、次の4ステップで確認すると整理しやすいと感じています。

  1. アセンブラ側の比較命令を確認する
  2. 分岐命令（BE、BNEなど）を確認する
  3. COBOL側のIF条件を確認する
  4. THEN／ELSEの処理内容を確認する

比較処理は派手な部分ではありませんが、オープン化ではこうした細かな確認の積み重ねが品質につながると感じています。

まとめ

今回のCLC確認では、比較結果そのものよりも、その後の分岐処理を重点的にチェックしました。
特にTHEN（真）とELSE（偽）の取り違えは、期待した結果にならない原因となるため注意が必要です。

CLC命令自体は単純な比較命令ですが、変換後の分岐ロジックまで含めて確認することで、思わぬ判定ミスを防ぐことができます。

アセンブラからCOBOLへの変換では、複雑なロジックだけでなく、このような基本的な比較処理についても丁寧に確認することの大切さを改めて実感しました。
オープン化案件では地道な確認作業が続きますが、一つひとつの積み重ねが品質向上につながると感じています。
